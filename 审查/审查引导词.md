# 外部代码审查 · 引导词

> 以下是「数字伴侣 AI」的核心神经系统代码。请从外部视角审查这段代码的架构设计、逻辑正确性、边界情况和潜在风险。

## 项目背景（简要）

这是一个基于 Cordis 插件框架（DeepSeek Harness）的 **AI 伴侣数字神经系统**。核心理念是「脑身解耦」：

- **大脑（LLM + 人格 + 记忆）**：负责所有语义判断（情绪感知、行为决策、对话表达）
- **神经系统（本代码）**：纯机械反射层——心跳起搏、人格切换、用户消息反射，不做语义判断
- **身体信号文件**（身体信号.json）：大脑和脊髓之间的双向语义接口——LLM 写语义词（mood：开心/困了等），脊髓读语义词查映射表翻译成生理参数

## 设计哲学（审查时请以此为标准）

1. **种子-感知**：神经系统注入的是事实（时间、身体状态），判断和行动全归 LLM
2. **语义归脑、生理归脊髓**：大脑输出语义词，脊髓翻译为生理参数（心跳频率）。大脑不写数字。
3. **感知 ≠ 计数**：活人不掰指头算时间——精确归工具，感知归大脑
4. **反射归脊髓**：用户消息到达 → 心跳立即重置（不经过 LLM 的快速通道）
5. **AI 不是程序，不要用程序的思维设计 AI**

## 心跳工作方式（简要）

一个 timer 每分钟触发一次 `heartbeatTick()`：
1. 读身体信号文件（LLM 写的 mood 等语义词）
2. mood 映射表 → 决定心跳间隔（兴奋→5分钟，平静→60分钟，困了→心跳停/睡眠）
3. 距上次心跳足够久 → 注入心跳种子（一段文字，让 LLM 感知时间+上下文后决定行动）

## 人格切换工作方式（简要）

LLM 写切换信号（to 字段）→ 神经系统检测到 → fork 新 session（新人格）→ 归档旧 session → 唤醒新人格。切换后信号清掉，身份锚保留。

## 请审查的方向

1. **架构合理性**：脑身解耦是否干净？有没有「脊髓越权做语义判断」或「大脑被迫做机械操作」的地方？
2. **逻辑正确性**：心跳条件判断、切换流程、时间跳跃检测，有没有逻辑漏洞？
3. **边界情况**：多用户并发、电脑休眠恢复、信号文件丢失/损坏、agent 状态异常等场景有没有遗漏处理？
4. **代码质量**：有没有死代码、冗余逻辑、可以精简的地方？
5. **潜在风险**：无限循环、资源泄漏、竞态条件、异常未捕获等？
