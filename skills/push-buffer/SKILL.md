# 推送缓冲池（push-buffer）

> 仓库是**公开**的。推前审阅是**隐私审查**，不是质量关口：扫的是文本内容，重点 md，出现隐私就涂抹或删除。代码质量另走分级审阅（`skills/engineering`），两道闸别混。

## 一、铁律

1. **推送只走缓冲池** `I:\SUE push buffer`（裸镜像）。本地 remote 凭证是坏的，禁止直推；`git push 本地路径` 会起 sh 失败——**同步只能"池侧 fetch"**（方向：池拉本地，不是本地推池）。
2. **token 在池内 `gh-token`**，由池内 `gh-credential-helper.sh` 消费——**永远不读取、不打印、不复制 token 内容**，凭证不得出现在任何命令或输出里。
3. 代理已写在池内 git config（`http(s).proxy = socks5h://127.0.0.1:8888`），不用另配。
4. **拿不准算不算隐私 → 先问老刘**（AGENTS.md 铁律）。

## 二、三步流程

### ① 池侧 fetch（把本地同步进池）

```
git -C 'I:\SUE push buffer' fetch 'I:\PJ sue' refs/heads/main:refs/heads/main
```

- 工作区沙箱内会报 `file access denied`（池在工作区外）→ **按规程升级重试同一条命令**（`danger-full-access`），理由写明"推送流程第一步"。
- 记下同步区间（如 `a5e7aff..8245ff3`），区间即审阅范围。

### ② 推前审阅（隐私审查 · 每次必过）

对区间内每个 commit：

- `git -C 'I:\SUE push buffer' show --stat <hash>` 看涉及文件；
- **重点扫 md/文本文件**：日记性记述、人名与家庭生活细节、住址/电话/账号、任何密钥或 token、`soul/`（人格记忆，本就不在库内）内容的转述——**出现即涂抹或删除，拿不准先问老刘**；
- 代码文件只扫**硬编码的密钥/凭证**，逻辑不审（那是分级审阅的事）；
- 结论口径：「纯文档→自审即推」适用的前提就是**这遍隐私扫描干净**。

### ③ 池内推送

```
git -C 'I:\SUE push buffer' push origin main
```

- 同样需要 `danger-full-access` 升级：要跑凭证助手（sh 进程）、经代理出网、写池内引用。
- 成功输出 `旧..新 main -> main` 即三方一致（本地 = 池 = 远端）。
- **审批会超时取消**：老刘不在电脑前时升级请求没人批就算了——**不轰炸重试**，等他回来说一声，重试同一条命令即可（10-10 实例：取消一次，重试即成）。

## 三、事后对账

- 给老刘报：同步区间、审阅结论（扫了什么、有无涂抹）、push 结果、升级审批消耗次数。
- 推的是代码/配置时，质量审阅报告须在**推送前**拿到他点头（本 SKILL 不替代 `skills/engineering` 纪律）。

## 教训（2026-10-10 首次成文）

- **"审阅"曾被理解成纯质量关口**——老刘校正：仓库公开，代码随便看；审阅挡的是隐私文本。隐私审查（每次必过）≠ 分级质量审阅（代码/配置另走）。
- `push origin` 报 `could not read Username` 不是凭证坏了，是**沙箱拦了凭证助手的 sh 进程**（`failed to execute prompt script`）→ 升级即可；不要去改 remote、不要内嵌 token 进 URL。
- 快照只是流程的速记，完整流程以本 SKILL 为准；快照 git 小节保留指针即可。
