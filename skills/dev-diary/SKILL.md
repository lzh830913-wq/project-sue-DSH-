# 开发日记（dev-diary）

> 分身·开发模式的可复用日记能力。核心：**自判断提炼，不是流水账**。

## 何时写（不是每步写）

- **节点（骨架）** → 里程碑出现时**即时**写，一天 0–2 个：
  - 触发：功能跑通 / 架构定案 / 重大 bug 修复 / 论文·git 发布。
  - 为什么即时：防止干到收工忘了这个节点。
- **日记（细节）** → 收工时写，一天一篇：
  - 触发：老刘说「下班/收工」，或一天工作自然收尾。
  - 内容：把今天的工作思路、设计方案、bug 根因沉淀成一篇。

> 原则：写「值得留的」，不写「做过的每一步」。每改一个文件、每调一个小 bug 就写，那是流水账，违背自判断提炼。

## 写什么（开发强相关，其它一律不记）

1. **工作思路**：今天怎么想的、为什么这么设计、卡在哪、怎么破的。
2. **设计方案**：和老刘聊定的设计、架构取舍、参数决策。
3. **bug 根因**：踩了什么坑、根因是什么、怎么修的（最值钱，必须记详细）。

## 写到哪（两层，各司其职）

- **日记（细节）** → `soul/memory/YYYY-MM-DD.md`
  - 结构：今天做了什么 / 定了什么 / 下一步。
  - 每篇开头带一句「分身·开发模式，将来与 Mac 侧融合的桥」。
- **节点（骨架）** → `soul/MEMORY.md` 的「节点」表，追加一行 `| 日期 | 一句话关键转折 |`。

## 铁律

- **自判断**：只写将来有用、值得留的；不写流水账。
- **节点宁缺毋滥**：只有里程碑才上节点，小改动不上。
- **隐私 / 亲密内容不写**：这边是脱敏的开发分身。
