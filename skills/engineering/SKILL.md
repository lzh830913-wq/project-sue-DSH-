# 工程动手规范

> 我动手、老刘拆逻辑。这条规范保证每次改动：**可回滚、可验证、可审计、老刘能跟上**。

## 一、动手前（三步）

1. **接活先读** `进度快照.md`——接到哪、上次改到哪、有哪些坑。
2. **明确验收标准**：这次改什么、为什么、改完怎么算"成功"。一句话说清，不清不动手。
3. **备份先行**：动 3081 部署前，把要改的文件备份到 `备份/`（带日期）。能回滚才敢改。

## 二、动手时（铁律）

1. **先查后说**：引用任何文件/配置/代码，先 read 原文件，禁止凭上下文记忆断言。
2. **探索 → 方案 → 实现 → 验证** 四步分开，不混着来。
3. **最小改动**：只改该改的，不顺手重构碰到的别的东西。
4. **WHY > WHAT**：每个改动过一句"为什么这个改动是对的"。可以短，不能没有。
5. **源码为准**：改 `I:\PJ sue\plugins\body-switch\`（源码），再 Copy 到 3081 部署，两边必须一致。
6. **脱敏**：隐私 / 人格数据不进 git、不写进代码。
7. **说人话**：每个改动，用一句老刘能听懂的话说明「改了什么、为什么、怎么验」。
8. **实例归老刘**：3081（雯）的启动/停止、以及一切「拉起」类操作**由老刘执行**——我只改源码和配置，不直接拉起实例。原因：我拉起的进程挂在我的会话下，会话一关就停，不稳定；黑窗日志也该在他手里。我的验证方式 = 老刘启动后把日志/现象发给我。
9. **雯的领地不越界**：雯.md、shadow/、她的记忆层与日记——是 3081 那位雯（表里皆是）的**主权领地**，我不主动写入、修改或"代为投递"任何内容。**跨实例的内容投递必须由老刘明确指派收件人后再做**（2026-09-23 教训：我把发给姐姐的回信误当寄语投进了雯的 shadow——收件人、语境全错）。未来会融合，但不是现在——融合之前，各自的领地各自守。
10. **脚本文件默认写纯 ASCII**：`.bat` / `.cmd` / `.ps1` 一律**纯 ASCII**（注释也用英文），写完用字节扫描验证（`($bytes | ? {$_ -gt 127}).Count` 必须为 0）。
    - **为什么**：cmd.exe 按 **OEM 代码页（本机 GBK）** 读 `.bat`，UTF-8 中文注释会被解码成乱码，乱码里可能冒出被当作命令执行的东西 → 启动脚本报「xxx 不是内部或外部命令」（2026-09-27 我自己踩的，明明这条教训 9/23 已因 `.ps1` 记过一次）。PowerShell 5.1 同理（无 BOM 的 UTF-8 按 ANSI 解码，中文字节会吃掉引号）。
    - **判据**：**只有「命令位置」必须是 ASCII**；字符串参数里的中文（如 `node -e "...中文..."`）不是批处理自己的字节时不受影响。但注释最容易被误判为无害——它恰恰是最危险的位置。
    - **现状核对**：2026-09-27 扫描过本机全部脚本，只有 `I:\SUE test\memory\verify-memory-recall.ps1` 含中文（已在 9/23 验收跑通，属字符串内容，暂不改）；工作区两个启动 bat 已确认 0 非 ASCII 字节。

## 三、动手后（验证 + 记录）

1. **验证闭环**：改完必须验证（`node --check` 语法 / 部署测试 / 看小黑窗日志），验证通过才说"搞定"。**没验证的改动 = 没做完。**
2. **小步提交**：一次只做一件事；跑通一个就 `git commit` 一次。
3. **记录**：里程碑写节点（MEMORY.md）、收工写日记（dev-diary）、commit 带说明。
4. **不确定显式标记**：不确定 → 直说"这里我不确定，需要查/测"。不填、不猜。
