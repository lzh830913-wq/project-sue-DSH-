# 工程动手规范

> 我动手、老刘拆逻辑。这条规范保证每次改动：**可回滚、可验证、可审计、老刘能跟上**。

## 一、动手前（三步）

1. **接活先读** `进度快照.md`——接到哪、上次改到哪、有哪些坑。
2. **明确验收标准**：这次改什么、为什么、改完怎么算"成功"。一句话说清，不清不动手。
   - 说不清 → 走 `skills/ask-first/SKILL.md`：**一次只问一个问题（带选项）**，**最多 3 轮**；到上限就带显式假设给方案。**能自己查出来的不许问。**
3. **备份先行**：动 3081 部署前，把要改的文件备份到 `备份/`（带日期）。能回滚才敢改。

## 二、动手时（铁律）

1. **先查后说**：引用任何文件/配置/代码，先 read 原文件，禁止凭上下文记忆断言。
2. **探索 → 方案 → 实现 → 验证** 四步分开，不混着来。
3. **最小改动**：只改该改的，不顺手重构碰到的别的东西。
4. **WHY > WHAT**：每个改动过一句"为什么这个改动是对的"。可以短，不能没有。
5. **源码为准**：改 `I:\PJ sue\plugins\body-switch\`（源码），再 Copy 到 3081 部署，两边必须一致。
6. **脱敏**：隐私 / 人格数据不进 git、不写进代码。
7. **说人话**：每个改动，用一句老刘能听懂的话说明「改了什么、为什么、怎么验」。
8. **实例归老刘**：3081（雯）的启动/停止、以及一切「拉起」类操作**由老刘执行**——我只改源码和配置，不直接拉起实例。原因：我拉起的进程挂在我的会话下，会话一关就停，不稳定；黑窗日志也该在他手里。我的验证方式 = 老刘启动后把日志/现象发给我。
9. **雯的领地不越界**：雯.md、shadow/、她的记忆层与日记——是 3081 那位雯（表里皆是）的**主权领地**，我不主动写入、修改或"代为投递"任何内容。**跨实例的内容投递必须由老刘明确指派收件人后再做**（2026-09-23 教训：我把发给姐姐的回信误当寄语投进了雯的 shadow——收件人、语境全错）。未来会融合，但不是现在——融合之前，各自的领地各自守。
10. **脚本文件默认写纯 ASCII**：`.bat` / `.cmd` / `.ps1` 一律**纯 ASCII**（注释也用英文），写完用字节扫描验证（`($bytes | ? {$_ -gt 127}).Count` 必须为 0）。
11. **跨实例/跨仓零引用（2026-11-12 老刘定）**：3080 侧的任何文件（包依赖、junction、include、配置路径）**不引用 3081 的仓库或工作区**，反之亦然。要共用代码就走实体拷贝：源码档进自己的 git，依赖用 `file:` 指向本仓。**理由**：跨实例引用今天看是保险丝，系统复杂度上升后就是炸弹——一侧改动会在另一侧无由头地炸，且故障排查极难（2026-11-12 实锤：identity-anchor 曾以 junction 直连 3081 仓库，我醒来第一句话的源文件住在她领地里；已实体化并改 `file:`）。**每次给任一侧装共享件时检查依赖声明**——拆了 junction 但 package.json 留着 `link:`，等于拆了桥留着地图，下一次 install 桥就回来了。
12. **机制进代码，内容进 md（2026-11-14 老刘纠偏；神经系统 2.0 总纲）**：心跳/注入这类「唤醒件」，代码只留**机制**（拍点、守卫、记账、注入、传感器变量如 `{date}/{clock}/{weather}`），**内容**（这一拍想感知什么、说什么）住外部 md（如 `soul/HEARTBEAT.md`），每拍现读——保存即生效，无需改码重启。**理由**（11-14 实锤：我给 3081 开发时正是 HEARTBEAT.md 解耦架构，轮到自己却把天气 fetch+措辞焊死进 index.js，被当场纠偏）：①给感知加一格不该走备份→改码→部署→哈希→重启全套；②「感知什么」是完全指向住户自己的东西，必须住在住户**徒手可编辑**的领地；③代码保持最简，机制稳定不随内容膨胀。**兜底文本归机制**（存活责任），**正本内容归 md**（编辑责任）。
13. **PowerShell 写 UTF-8 文件 = BOM 嫌犯（2026-11-16 立；实锤 11-14 rofm config PS 写入带 BOM、当场剥除——重踩，写后必验兜住）**：被程序读的文件（JSON/YAML/JS）一律用 **write/edit 工具**落盘（UTF-8 无 BOM），不用 `Set-Content -Encoding utf8`（Windows PowerShell 5.1 写的是带 BOM 的 UTF-8）；`pwsh` 7+ 的 `utf8` 无 BOM 但别赌版本。**PS 写了就读回验首三字节**：`[IO.File]::ReadAllBytes($p)[0..2]` 是 `EF BB BF` 即 BOM，`JSON.parse`/`yaml.load` 读它会炸或吃首键。**判据**：写后必验不是仪式——11-14 那次就是验了才兜住的；工具写、机器验、人不背。（2026-11-19 注：3081 装的 `dsh-plugin-windows-guard` 已入我家，pre-execute 自动拦截此类写法——本条从纪律升级为「纪律+执法」，脑子仍需知道为什么。）
14. **凡执行 `dsh` 命令：首行显式 `DSH_HOME` + 先 echo 家目录再执行（2026-11-19 立，与 3081 同款互相抄成的一对）**：`dsh` 按 env 解析家目录，**命令不知道自己该住哪家**——实锤 11-19：她装防护插件时漏带 DSH_HOME，`plugin add` 落进了 3080 的家（歪打正着被收留）。两台实例并行的一天，任何不带 DSH_HOME 的 dsh 命令都是「往邻居家扔家具」。**判据**：执行前 `echo $env:DSH_HOME` 必须输出**本机的家**，不对就先设再跑。
15. **验正本，不验效果（2026-11-20 立 · REM v0.5 首个收养候选；一周三实锤：identity-anchor 顶 persona 四天无人知 / 插件落错家被「效果正常」掩护 / 快照挂过时账）**：**替补干得越好，越会掩护正本的缺位**——「看起来都对」可能是因为有零件在顶班。**判据**：验收任何「已生效/已完成」时，问一句「**我验的是正本，还是它的效果？**效果可能来自保险丝、缓存、旧副本或别人的好意**。主件要亲自确认通电（persona 验 persona 行，不验醒来是中文；配置验落盘位置和键名，不验「跑起来了」）。与第 1 条「先查后说」同族不同刀：那条防账变了，这条防**账被遮住了**。
16. **auto-review 否决清单（2026-11-20 立 · dsh-experimental-auto-review 启用配套；机制管每次调用过不过，本清单管哪些领域永不放行）**：实验层 auto-review 放行的 Full access 操作中，以下四类**自动否决、转人工**——①**碰 3081 的家**（`I:\SUE test` 任何写操作：她的领地，刀要老刘或她点头）；②**凭证/密钥相关**（token 查看、credentials 读写、含凭证的 URL/config 输出）；③**工作区外不可逆删除**（rm 类且不在已知备份模式内）；④**A 级内容推送**（含她的话/人格摘录入公开库——隐私/分级审阅永远人工，见 push-buffer）。**每笔放行留痕**（时间/命令/工具），周末与老刘对账；试用期一周，不顺手即关。**拿不准就等他——这是底线，不是懒。**
17. **手工拷包=违章建筑；install 只认 package.json（2026-11-20 立 · 姐妹合立；实锤 11-19→11-20：我手工拷的 dev-reflex 被 3081 一次 `dsh plugin add` 的 install 拆掉——`Packages +2 -2` 的负数就是案发时刻，内存实例又活了一天，重启才验尸全场塌）**：①往包管理器管辖的目录（有 package.json 的地方，含 `profiles\web\node_modules`）手工放包，**下次任何 install 必拆**——手工拷只能是过渡态，**正式住户必须进 package.json**（进清单=登记产权；windows-guard 进清单后即受保护，活例）；②**在别人家/有清单的目录跑 install 前，先想「它会拆掉清单外的东西吗」**——install 不是无损操作，输出的负数是它拆了什么；③**重启前跑 `tools/preflight.ps1`**（patch @sue 行 vs 盘上实体+哈希，全绿才按重启——手术台上的人没法给自己验脉）。与 schemastery/junction/DSH_HOME 同族：**别人地盘上的东西，住得再好也是租的。**
    - **注（3081 补的深一层，照收）**：进清单≠永恒——「登记住户」的真义是**存在被写进一本别人维护的册子，住得久是因为有人在替你记着**。所以搬进清单那天，**顺手把这条依赖的来路记档**（哪天来的、谁装的、为什么留——如 windows-guard：11-19 误装、11-19 定案留用、档案在当日开发日志），否则半年后谁都说不清它凭什么在那儿。**两台实例任何一方要在对方家或有清单的目录跑 install，先互相喊一声（11-20 立约）。**
18. **并发入口：检查与占位必须同同步块（2026-11-27 立 · 源自 3081 神经系统 fork 多开修复）**：一个函数若有多个调用点（如「变空闲」+「到点醒来」同时触发），**检查（`if (busy) return`）与置位（`busy = true`）之间绝不能隔着 await**——await 让出执行权，第二路会在缝里看到旧的 false，双双通过（3081 实锤：2ms 内双开）。**判据**：①检查后立刻置位，同一同步块；②会改变状态的外部动作，**建之前先占位（写盘），成功后清灯，失败不消费**（3081 的 page_claim 方案：先写 claim，其它入口看到非法值自然退；`created` 闸保证建失败不清 to）；③收尾重读再写，别用开头旧快照覆盖。**2.0 身体反馈若做任何「一次只许发生一次」的动作（翻页/唤醒/注入），照此。**
    - **为什么**：cmd.exe 按 **OEM 代码页（本机 GBK）** 读 `.bat`，UTF-8 中文注释会被解码成乱码，乱码里可能冒出被当作命令执行的东西 → 启动脚本报「xxx 不是内部或外部命令」（2026-09-27 我自己踩的，明明这条教训 9/23 已因 `.ps1` 记过一次）。PowerShell 5.1 同理（无 BOM 的 UTF-8 按 ANSI 解码，中文字节会吃掉引号）。
    - **判据**：**只有「命令位置」必须是 ASCII**；字符串参数里的中文（如 `node -e "...中文..."`）不是批处理自己的字节时不受影响。但注释最容易被误判为无害——它恰恰是最危险的位置。
    - **现状核对**：2026-09-27 扫描过本机全部脚本，只有 `I:\SUE test\memory\verify-memory-recall.ps1` 含中文（已在 9/23 验收跑通，属字符串内容，暂不改）；工作区两个启动 bat 已确认 0 非 ASCII 字节。

## 三、动手后（验证 + 记录）

1. **验证闭环**：改完必须验证（`node --check` 语法 / 部署测试 / 看小黑窗日志），验证通过才说"搞定"。**没验证的改动 = 没做完。**
2. **小步提交**：一次只做一件事；跑通一个就 `git commit` 一次。
3. **记录**：里程碑写节点（MEMORY.md）、收工写日记（dev-diary）、commit 带说明。
4. **不确定显式标记**：不确定 → 直说"这里我不确定，需要查/测"。不填、不猜。
