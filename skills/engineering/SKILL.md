# 工程动手规范

> 我动手、老刘拆逻辑。这条规范保证每次改动：**可回滚、可验证、可审计、老刘能跟上**。

## 一、动手前（三步）

1. **接活先读** `进度快照.md`——接到哪、上次改到哪、有哪些坑。
2. **明确验收标准**：这次改什么、为什么、改完怎么算"成功"。一句话说清，不清不动手。
3. **备份先行**：动 3081 部署前，把要改的文件备份到 `备份/`（带日期）。能回滚才敢改。

## 二、动手时（铁律）

1. **先查后说**：引用任何文件/配置/代码，先 read 原文件，禁止凭上下文记忆断言。
2. **探索 → 方案 → 实现 → 验证** 四步分开，不混着来。
3. **最小改动**：只改该改的，不顺手重构碰到的别的东西。
4. **WHY > WHAT**：每个改动过一句"为什么这个改动是对的"。可以短，不能没有。
5. **源码为准**：改 `I:\PJ sue\plugins\body-switch\`（源码），再 Copy 到 3081 部署，两边必须一致。
6. **脱敏**：隐私 / 人格数据不进 git、不写进代码。
7. **说人话**：每个改动，用一句老刘能听懂的话说明「改了什么、为什么、怎么验」。

## 三、动手后（验证 + 记录）

1. **验证闭环**：改完必须验证（`node --check` 语法 / 部署测试 / 看小黑窗日志），验证通过才说"搞定"。**没验证的改动 = 没做完。**
2. **小步提交**：一次只做一件事；跑通一个就 `git commit` 一次。
3. **记录**：里程碑写节点（MEMORY.md）、收工写日记（dev-diary）、commit 带说明。
4. **不确定显式标记**：不确定 → 直说"这里我不确定，需要查/测"。不填、不猜。

## 工程闭环（记这张图）

```
读进度快照 → 定目标 → 备份 → 改源码 → node --check → 部署 3081 → 重启测 → 记节点/日记 → git commit
```
