### 3. 心跳验证卡住 → 深挖根因（今天最值钱的因果）
- 现象：日志里 `心跳 tick: idle=false hasAgent=false` 一直不触发。
- 排查链：

- 铁律：**host 插件监听 agent 事件，不加 {global:true}**（host 上下文无标签，天然全局）。

### 4. 项目重定位讨论（从「插件」到「发行版」）
- 起因：心跳卡住暴露深层问题——「没有主体 session 概念，不知道谁是发信号的人」。
- 老刘核心判断：伴侣 AI ≠ 工程 AI；工程一个任务一个 session，伴侣要「连续活着的身体」+ 主体 session。
- 借鉴 OpenClaw（思路，不照抄源码）：查证了 `sessionKey "agent:main:main"` 是「标记」不是「固定 session 号」（Session Key 稳定、Session ID 会变）；session ≠ 通道；单一独占；醒来增量。
- 结论：项目 =「DSH 伴侣发行版」= DSH 原封不动 + 伴侣层（preset 脑子 + host 身体 + client 门），不是 fork、不是单一插件。

### 5. 查证闭环（DSH 能力）
- 能加第 5 种模式：preset 目录 + preset.yml，选择器自动出现。
- 「模式」= preset，建 session 时与「工作区」一起选（`conversation.hero.agentPreset` 芯片 + 工作区选择器并排）。
- `workspace.create` 只收 `{path}`（无 mode 字段）→ 单 session 由 host 执行，不靠建区弹窗。
- host 读「session 挂哪个 preset」：`ctx.agentPresets.composedPreset(agent.ctx)`（从活 scope 链读）。
- fork 子 session 绑父组合：`composeFrom(agentCtx, parentCtx)`（同一代，不重读 roster）优于 `mount(resolvedId)`。

## 决策记录

1. 伴侣 AI ≠ 工程 AI：伴侣要跨 session 的身体（host daemon）。
2. 三层：preset（脑子）+ host（身体）+ client（门）。
3. 单 session 靠「消除」不靠「判定」：窗口永远一个，主 session = 唯一的那个。
4. 醒来流程线性 + 增量：表读基线，里多读 shadow 三样。
5. 红线：preset 真实人格不进 git（gitignore `presets/companion/agent.cordis.yml`）。
