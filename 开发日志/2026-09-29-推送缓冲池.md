## 踩的坑（三个，都值得记）

1. **裸仓库没有 `.git` 子目录**——第一版脚本写 `$(dirname "$0")/../.git/gh-token`，路径多一层；实际 token 文件与 `config` **同级**（`I:\SUE push buffer\gh-token`）。
2. **系统级 gitconfig 挂着 `helper = manager`**（Windows 凭据管理器）。它里面有 **`lzh6300` 账号**的旧条目，与本仓库要用的 `lzh830913-wq` **不匹配**——会让 git 拿错账号的凭据。解法：池子里配 **`helper =`（空，清空继承链）+ `helper = gh-credential-helper.sh`**。
3. **PowerShell 写 git config 会咬引号**：`git config credential.helper "!sh \"...\""` 的结果是 `helper = !sh \" I:/SUE.../gh-credential-helper.sh\\`——**配置被写坏**。最终用 Python 按行重写 `[credential]` 段才干净。（同类教训：9/27 的 `.bat` 编码坑也是"工具链会改写你写的东西"。）

## 教训

- **"审阅"和"操作"要物理隔离**：同一个目录里既审又改，误操作概率不为零；**池子把审阅对象变成副本**——这条思路可以复用到别处（如改生产配置前先复制一份比对）。
- **凭证不进 config**：token 放独立文件 + 自定义 helper，池子的 `config` 就永远是可以给人看的东西。
- **别信工具的"默认"**：`credential.helper` 默认会继承系统级设置（`manager`），一个"没配过"的仓库其实**早有助手在跑**——排查认证问题必须先看 `--show-origin` 级的全链。
