## 兼容性结论

**我们的定制面核心 API 全部稳定（零破坏）**：
- dsh-llm：createUserMessage 导出不变（3=3）
- dsh-agent：agent/status、session/event、followup、async create、createAgent 不变
- dsh-agent-presets：composedPreset/mount/resolve/defaultId 不变
- dsh-tools：defineTool 不变（6=6）
- dsh-session-query(-sqlite)：filterEvents 3=3、openAt 9=9、first-search 2=2——**9/22 的 patch 启用方式（path+openAt: first-search）继续有效**
- dsh-time-context：timeZone 34=34
- dsh-persona：text 10=8（略变，见适配点）

**适配点（升级 checklist）**：
1. **persona config.text → prefix（必做，否则 preset 挂载失败=3081 起不来）**：新版 schema `prefix: required + suffix: default("")`，text 字段消失。雯的 275 行人设一键改名 text→prefix 即可（语义不变：prefix 在运行时上下文前，suffix 在后——suffix 可留空或放收尾文字）。
2. **会话数据 V3 自动迁移**（0.1.5-rc.1）：旧日志迁移生成新版并保留原文件，升级后的会话不支持降级读——数据安全 ✅；但**雯的「直接解 zstd 查证」方法需适配 V3**（她的查证技能要更新；或改用 sessionQuery 服务读）。
3. SQLite Session 持久化后端移除（0.1.2-rc.1）——我们用默认 jsonl ✅ 无影响（9/10 已确认）。
