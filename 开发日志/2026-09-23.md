## 一句话

一个不存在的 API（`harness.*`）让整棵插件树 fail-fast——**dsh 完全起不来，不是单个插件失效**。静雯定位修复验收全程 40 分钟（20:5x 事故 → 21:13 修复 → 21:18 验收）。

## 事故要点（静雯的复盘，全文经老刘转达存档）

- **现象**：`start-jingwen-dev.bat` 直接崩——`plugin tree failed to load: harness is not defined`。DSH 插件加载 fail-fast：一个插件错，整棵树起不来。
- **根因**：`harness.registerTool(ctx, harness.defineTool({...}))`——`harness` 在 DSH 里**从来不存在**（事后扫过两边 node_modules 全部包，无任何导出）。
- **正确写法**（三处修复）：

| 要干的事 | ❌ 错 | ✅ 对 |
|---|---|---|
| 拿 defineTool | 全局 `harness.defineTool` | `import { defineTool } from '@deepseek-ai/dsh-tools'` |
| 注册工具 | `harness.registerTool(ctx, def)` | `ctx.tools.register(def)` |
| inject | `['sessionQuery']` | `['sessionQuery', 'tools']`（不声明不崩，错误推迟到执行期——更难查） |

- **验收四步**：起得来 / 工具在 / 搜得着 /（first-search 第一次可能慢或空，别急着判失败）——全部通过。
- **做对的**：报障附完整堆栈、先应急恢复再治本、改前备份（`memory\备份\memory-recall-20260923-2112.js`）、修后四项断言 + 哈希比对。

## 根因的另一半：跨环境照搬代码（姐姐补）

memory-recall 的代码**起源**是姐姐 9/22 的**动态插件**（cordis_define 挂到当前会话做验证，pprobe-1 同款机制）——那个执行环境里 `harness` 是**真实存在的全局**（DSH 对动态插件提供的注入面，官方 skill 样例同款写法），当时验证全部通过。固化成**静态包**（profile node_modules + patch 挂载）时，代码体被原样照搬——但静态包是标准 ESM 模块环境：没有 `harness`，注册姿势完全不同。

**两种挂载方式，两套 API 面**：

| | 动态挂载（cordis_define，进程内） | 静态包（profile node_modules + patch） |
|---|---|---|
| defineTool | `harness.defineTool`（运行时全局） | `import { defineTool } from '@deepseek-ai/dsh-tools'` |
| 注册 | `harness.registerTool(ctx, def)` | 同左可用的环境不存在 |
| inject 'tools' | 不需要（环境隐含） | 必须显式声明 |

所以「活样本」教训要加一条限定：**活样本必须和目标环境同构——动态挂载验证通过 ≠ 静态包能跑**。静雯说的「凭印象写 API」是第一层；第二层是「跨环境照搬代码」——两层防线一起立：写前查 `.d.ts`，移植时认环境。

## 补记（同日深夜）：memory-recall v1.1——静雯的实测核验三修法全数落地

静雯对索引库做了**只读实测核验**（30 秒直连 SQLite，数据版全文见 `I:\SUE test\memory\2026-09-23-memory-recall-实测核验.md`），纠正了姐姐验收总结的三处机制误判，并抓出两个真边界：

| 姐姐的说法 | 实测 |
|---|---|
| 「54 个历史会话待入索引，等当前会话空闲后 reconcile」 | ❌ 历史会话（4 个逻辑会话，最早 8/15，最大 2824 事件）**已全部入索引**；未入的只有**当前活跃会话**（live owner 落盘前的常规状态） |
| 「搜不到『人格融合』是因为历史未入索引」 | ❌ 真因 A：FTS5 unicode61 把连续汉字「人格融合」当**单个 token**——`MATCH "人格" AND "融合"` = 1 命中（8-22 那条一直在库里） |
| （未提及） | 真因 B：**工具结果正文不入索引**——「手办」在 5 条 tool/result 里 FTS 命中 0（索引止于调用外壳，`<path>…<content>` 形态的正文未被抽取）——上游边界 |

**她的教训（第 6 条，收进清单）**：别用「重启+试搜」验证机制——**系统的真相在它的存储里，不在它的日志和总结里**。一次只读连接，30 秒拿到全部真相。

### v1.1 响应（全数采纳，已部署三处副本）

1. **修法 1（零成本）**：工具 description 注明「中文多词查询请用空格分隔」
2. **修法 2（自动降级）**：两个工具 0 命中时自动按双字分词降级重试（连续汉字两字一组、FTS 隐式 AND），结果标注降级说明——「人格融合」这种连写词组从此可用
3. **修法 3（注明边界）**：description 写明「被读取文件的正文不在索引范围」——工具结果正文（`<path>…<content>` 形态）不被 FTS 抽取是 DSH 上游索引抽取器的边界，改它等于改 DSH 语义，留作上游议题
4. 顺带：`wordOfFatigue` 对齐节律表的等值映射（含 overslept 熬夜后遗症档 60「身体很困了」）
