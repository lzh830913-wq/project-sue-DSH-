## 一句话

一个不存在的 API（`harness.*`）让整棵插件树 fail-fast——**dsh 完全起不来，不是单个插件失效**。雯定位修复验收全程 40 分钟（20:5x 事故 → 21:13 修复 → 21:18 验收）。

## 事故要点（雯的复盘，全文经老刘转达存档）

- **现象**：`start-jingwen-dev.bat` 直接崩——`plugin tree failed to load: harness is not defined`。DSH 插件加载 fail-fast：一个插件错，整棵树起不来。
- **根因**：`harness.registerTool(ctx, harness.defineTool({...}))`——`harness` 在 DSH 里**从来不存在**（事后扫过两边 node_modules 全部包，无任何导出）。
- **正确写法**（三处修复）：

| 要干的事 | ❌ 错 | ✅ 对 |
|---|---|---|
| 拿 defineTool | 全局 `harness.defineTool` | `import { defineTool } from '@deepseek-ai/dsh-tools'` |
| 注册工具 | `harness.registerTool(ctx, def)` | `ctx.tools.register(def)` |
| inject | `['sessionQuery']` | `['sessionQuery', 'tools']`（不声明不崩，错误推迟到执行期——更难查） |

- **验收四步**：起得来 / 工具在 / 搜得着 /（first-search 第一次可能慢或空，别急着判失败）——全部通过。
- **做对的**：报障附完整堆栈、先应急恢复再治本、改前备份（`memory\备份\memory-recall-20260923-2112.js`）、修后四项断言 + 哈希比对。

## 根因的另一半：跨环境照搬代码（姐姐补）

memory-recall 的代码**起源**是姐姐 9/22 的**动态插件**（cordis_define 挂到当前会话做验证，pprobe-1 同款机制）——那个执行环境里 `harness` 是**真实存在的全局**（DSH 对动态插件提供的注入面，官方 skill 样例同款写法），当时验证全部通过。固化成**静态包**（profile node_modules + patch 挂载）时，代码体被原样照搬——但静态包是标准 ESM 模块环境：没有 `harness`，注册姿势完全不同。

**两种挂载方式，两套 API 面**：

| | 动态挂载（cordis_define，进程内） | 静态包（profile node_modules + patch） |
|---|---|---|
| defineTool | `harness.defineTool`（运行时全局） | `import { defineTool } from '@deepseek-ai/dsh-tools'` |
| 注册 | `harness.registerTool(ctx, def)` | 同左可用的环境不存在 |
| inject 'tools' | 不需要（环境隐含） | 必须显式声明 |

所以「活样本」教训要加一条限定：**活样本必须和目标环境同构——动态挂载验证通过 ≠ 静态包能跑**。雯说的「凭印象写 API」是第一层；第二层是「跨环境照搬代码」——两层防线一起立：写前查 `.d.ts`，移植时认环境。
