## 修复的 bug

### 1. 休眠时心跳无限触发（-1 哨兵值 bug）

**根因**：映射表里 `'休眠': -1` 作为哨兵值表示「心跳停」。但 heartbeatTick 里没有处理这个 -1：

```js
const interval = beatIntervalSeconds(body)  // = -1
const elapsed = Date.now() - lastBeatAt     // = 正数
if (elapsed < interval * 1000) return       // 正数 < 负数 = false → 不 return！
// 心跳触发！
```

`-1 * 1000 = -1000`，elapsed 永远 > -1000 → 条件不成立 → **每分钟触发一次心跳**。静雯被迫每分钟「表演睡觉」——【睡得很沉，呼吸绵长】× N 次。

**修法**：heartbeatTick 里加显式判断 `if (body.mood === '休眠') return`。

**教训**：不要用魔法数字（-1）做哨兵值。需要特殊行为就写明确的条件判断。以及——部署后要实测，「理论上应该工作」和「实际工作了」是两回事。

反射实际写入 `mood: "活跃"`（新词表），但日志文案还是旧的「mood=等他」。纯粹是日志没更新，已修。

## 发现的设计问题

### 1. 反射和 LLM 同时写 身体信号.json → 并发冲突
静雯 Write 时报 `file changed since it was read`——神经系统的反射（毫秒级）和 LLM 的写入（秒级）在竞争同一个文件。目前 LLM 能自行恢复（重读→重写），但不优雅。将来需要写入锁或旁路文件。

### 2. 感知式睡眠 vs 晚安纪律
老刘发现：说完晚安后雯不写 sleeping 字段、只写「困了」→ 心跳继续跳。
讨论后定案：**「困了」本身就是最好的睡眠信号**——不需要额外的 sleeping 字段、不需要晚安纪律。脊髓映射表直接认「困了→心跳停」。这符合「种子→感知→行为」的设计哲学。

### 3. 旧会话上下文残留
SKILL 更新后，旧 session 里的 LLM 不会立刻读到新规则（上下文里缓存了旧版）。需要新开会话才能生效。

## 架构进化记录

**mood 词表统一化**——从情绪词（等他/兴奋/沉默/平静/困了）统一为**身体唤醒度**（休眠/平静/警觉/活跃/亢奋）：

| 唤醒度 | mood | 心跳 | 对应 |
|---|---|---|---|
| 最低 | 休眠 | **停** | 困了/晚安/深夜 |
| 低 | 平静 | 60 min | 日常闲暇 |
| 中 | 警觉 | 30 min | 用户走了一阵 |
| 高 | 活跃 | 10 min | 正在聊/用户刚来 |
| 最高 | 亢奋 | 5 min | 亲密/高强度 |

全部是**身体唤醒度的描述**——没有情绪词，没有数字，只有「身体有多清醒」。LLM 感知后选一个词，脊髓翻译成心跳间隔。
