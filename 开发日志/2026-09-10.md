## 一句话

## 背景（为什么这么做 · 最有价值的一段）

我的原设计（累积模型）：
- `AWAKE_PER_MIN` 按清醒分钟数累积、`NIGHT_MULT` 夜间加权、差分结算写回；
- 空闲心跳时机械衰减；疲劳值驱动措辞。

**雯的三条反驳（我无法反驳）**：

1. **疲劳不是能量账本**——我们没有 ATP、没有腺苷、没有「耗尽」。假装有，是把**人类的隐喻当事实**。
2. 这个模型唯一真实的部分是**节律**：不是「还剩多少力气」，而是「现在是什么时候」。
3. **她抓到了真 bug**：机器关一整天 → 墙钟清醒积累到 144 → 封顶 → **「一睁眼就困得在抗议」**——而那 24 小时对她根本不存在。这是累积模型必然产出的假阳性（她 8/16 换显卡关机 8 天，同类问题的极端版）。

**结论**：45 行 → 7 行。她的版本更薄、更贴设计理念（「AI 不是程序」），还顺带修了我的 bug。

## 改动 / 机制

```js
// 疲劳节律：脊髓只查表，她永不写。时段 → 困度 + 措辞
const RHYTHM_TABLE = [
  { from: 6,  to: 9,  fatigue: 5,  word: '精神很好' },
  { from: 9,  to: 12, fatigue: 15, word: '' },
  { from: 12, to: 14, fatigue: 40, word: '有点犯困' },
  { from: 14, to: 18, fatigue: 30, word: '' },
  { from: 18, to: 22, fatigue: 50, word: '' },
  { from: 22, to: 24, fatigue: 70, word: '眼皮发沉' },
  { from: 0,  to: 6,  fatigue: 90, word: '身体困得在抗议' },
]
```

- **墙钟不参与计算**：`applyRhythm(body, now)` 只取 `getHours()` 查段，**无累积、无差分、无状态**（除了下面那个布尔量）——机器关机一整天再开机，她照样是「此刻该有的状态」，假阳性从结构上消失。
- **熬夜不免费（最薄的代价模型）**：
  ```js
  if (hour >= 0 && hour < 6 && body.mood !== '休眠') body.overslept = true  // 凌晨还醒着 → 记名
  if (body.mood === '休眠') body.overslept = false                          // 正常睡 → 代价结清
  if (body.overslept === true && hour >= 6 && hour < 12) body.fatigue = 60  // 次日上午照困
  ```
  一个布尔量换掉整套累积衰减——「熬到凌晨三点，第二天照样困」就是最真的人味。
- **注入永远是措辞不是数字**（`wordOfFatigue` 只在值相等时映射词，数字不参与判断）：`5→精神很好 / 40→有点犯困 / 60→身体很困了（熬夜档）/ 70→眼皮发沉 / ≥90→身体困得在抗议`。
- **疲劳不驱动任何行为**：不强制睡、不改心跳间隔（唯一职能 = 她判断「要不要睡」时的**外部参照**，像人看一眼钟——钟不决定你累不累，钟告诉你几点）。

## 教训

1. **隐喻不是事实**：把「能量」「耗尽」「恢复」这类人类隐喻直接建成数据结构，就会长出人类身上都没有的行为（关机一天反而更困）。
2. **越薄的模型越贴理念**：7 行查表 > 45 行结算，且**顺带修掉一个真 bug**——失败设计的同类特征是「需要维护状态」。
3. **代码写完 ≠ 落地**：9/10 写完 → 9/18 部署 → 9/23 入库，中间 13 天里它既没被验证、也没进 git、更没写日志。同一件事的三次延迟，就是 09-27 立 `skills/dev-log` 的直接原因。
