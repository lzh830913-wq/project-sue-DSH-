## 一句话

给「记忆」装上数据库把手：DSH 自带的 `sessionQuery`（SQLite + FTS5）从内存态改成**落盘持久索引**，并包一层 `@sue/memory-recall` 工具（跨会话搜 + 会话内深挖）——从此「当初为什么这么改」可以查，而不是靠记忆。

## 背景（为什么这么做）

- 我之前回答「当初为什么这么改」只能靠：翻文件、看 git log、或者**凭印象断言**（违反「引用文件先读原文件」铁律）。
- DSH 自带 `session-query-sqlite` 插件，但默认配置是 `:memory:` + `openAt: never`——**索引只活在进程内、且从不打开**，等于没开。
- 老刘的决定：**启用，但只在本机**——索引只含本机会话数据，不出机器。

## 改动 / 机制

### 1. 底层：持久索引（patch 覆写，不改 DSH 本体）

```yaml
# C:\Users\lzh_6\.dsh\profiles\web\cordis.patch.yml
- id: session-query-sqlite
  config:
    path: 'C:/Users/lzh_6/.dsh/session-index.db'
    openAt: first-search        # 不用 never；首次搜索时才打开，不拖启动
```

### 2. 把手：`@sue/memory-recall`（两个工具，profile patch insert 挂载 → **所有预设共享**）

| 工具 | 作用 | 上限 |
|---|---|---|
| `memory_search_sessions` | **跨**全部历史会话全文搜索，每会话返回最佳命中片段 | limit 默认 8 / 上限 20 |
| `memory_search_events` | **单**会话内深挖事件（定位到会话后再钻细节） | limit 默认 10 / 上限 30 |

- 实现要点：`export const inject = ['sessionQuery', 'tools']`；`ctx.tools.register(defineTool({...}))`；输出统一走 `render()` 成纯文本。
- 时间格式化走 `toISOString().slice(0,16)`，片段走 `clean()` 压空白后截断（320 / 280 字符）。

### 3. 只读实测核验（当晚，30 秒直连 SQLite）

实测纠正了三处机制误判，见 `开发日志/2026-09-23.md` 补记：**FTS5 `unicode61` 把连续汉字当一个 token**（「人格融合」搜不到 → 需空格分隔）；**tool/result 正文不入索引**（上游抽取器边界）。

## 怎么验的

- 索引库实读：`persisted_docs` = 4064 条，按会话分布可查（用 python `sqlite3` 直连，无需启动 DSH）。
- 工具可调：两个工具在会话中可直接调用并返回片段。
- **实测发现两个真边界**（已写进工具 description，防止后来者误判）：中文连写需空格分隔；被读取文件的正文不在索引范围。

## 教训

- **「系统的真相在它的存储里，不在它的日志和总结里」**（09-23 补记，教训第 6 条）——一次只读连接胜过「重启+试搜」。本文的机制描述也全部来自实读源码与数据库，不来自记忆。
- **能力上线 ≠ 数据可用**：索引建好了、工具能调，但**数据没进来**，效果等于零。凡是「索引/缓存/回填」类功能，验收标准必须包含**内容断言**（例如「搜一个已知存在的旧词，必须命中」），不能只看「工具返回 200」。
