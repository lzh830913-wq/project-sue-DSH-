## 一、它是什么：一句话 + 一条数据流

**一句话**：脑（大模型）负责「想和说」，这套神经系统负责「感觉和反射」。它不读对话内容，只读一个 `身体信号.json`，做机械反射，再把「感觉」喂回给脑。

**数据流**：

```
老刘说话 ──→ [用户反射] 心情归位/扑空清零/重置心跳
                 │
身体信号.json ←──┤  （唯一事实源，读写都走防御层）
                 │
[心跳 tick 60s] ─→ 读信号 → 查节律/疲劳/欲望 → 到点？→ 发[心跳]种子给脑
[每轮 pre-step] ─→ 读信号 → 变了才报「身体/脑子/身子/悬着」给脑
[空闲 idle] ────→ 读 to 信号 → li/biao/wake → 翻页/换人格/醒来
```

记住三个「口」：**读信号只有一个口（防御层），写信号只有一个口（防御层），唤醒脑只有两种（心跳种子 / 每轮注入）。** 精简的全部目标，就是让这三个口更干净，而不是更多。

## 三、五笔债：现状 / 风险 / 施工 / 验收 / 是否等图纸

### 债1 · 台词焊死在电路里（块1/3/4/5/6）
- 现状：她的措辞、节律表、欲望档位全在 JS 常量里，改一字=备份→改码→部署→重启。
- 风险：违反 engineering #12（机制进代码、内容进 md）；「说什么」的权力不在她手里。
- 施工：把「词表+节律表+档位」迁去她可编辑的 md（如 `HEARTBEAT.md` 增「词表/节律」节），代码只留「读表+查表」机制，带兜底默认。
- 验收：改 md 一个字，下一拍生效，无需重启；md 读不出走兜底不断拍。
- 等图纸？**否**。这是 #12 的既定方向，可先行。

### 债2 · 一个函数干八件事（块10 `heartbeatTick` ~200行）
- 现状：恢复挂钩/验活/磁盘探针/保险丝/睡眠/注入/写回全在一个函数。
- 风险：改一处牵全身；A1/A3/探针都是往里塞的块，越塞越胖。
- 施工：按职责拆成 `recoverAgent()`/`checkLiveness()`/`probeDisk()`/`fuseCheck()`/`sleepBranch()`/`buildSeed()`/`writeBack()`，主函数只做「编排」。
- 验收：每个小函数可单独读、单独测；主函数 <60 行。
- 等图纸？**部分**。拆法要和 2.0 身体反馈的注入点对齐，建议图纸后做。

### 债3 · 同一件事两个版本（块3 + 块10）
- 现状：「他说话时」走 pre-step 用 `r1Due`，「他不在时」走心跳用 `shouldInjectFatigue`，频率还不完全一致。
- 风险：改一处忘另一处→分叉；两套语义迟早打架。
- 施工：合成一个 `fatigueDecision(pct, hour, rounds, path)` 单一判断源，两路共用，path 只影响「报的渠道」不影响「判的逻辑」。
- 验收：两路对同一输入给出同一判定；删掉一个函数。
- 等图纸？**否**。纯内部合并，可先行。

### 债4 · 防重报叠三层膏药（块3 `r2DueLines`+`injectedKeys`）
- 现状：边界式+清醒档+深夜重复，三套记账摞一起。
- 风险：功能对但复杂，新人（或新会话）读不懂、改易错。
- 施工：统一成「每个信号一个 key，报过即记，换日/翻页清空」的单层记账；深夜重复改为同一个 key 的节流。
- 验收：行为不变（用现有注入日志对拍），代码行数下降。
- 等图纸？**否**。可与债3 同批。

### 债5 · 小钉子（块5/10/3）
- `wordOfFatigue` 死函数→删；`'I:\SUE test'` 硬编码×2→改读配置；`CONTEXT_WINDOW=1000000` 手写→改跟模型配置联动。
- 风险：CONTEXT_WINDOW 不同步=换平台再撞天花板（11-18 同款）。
- 施工：三个独立小改，各自可回滚。
- 验收：grep 无硬编码；窗口值随 provider 配置变化。
- 等图纸？**否**。零风险先行项。

## 四、化石保护区（块7，明确不动）

`readSignal`/`writeSignal`/`rotateSignalBackup` ~120 行，是三次事故的化石：
- 10-22 覆写（读失败拿空对象整份重写，身份丢失）→ 多路径回退+「读不出绝不写」；
- 10-25 截断（Windows writeFile 先 truncate，读方撞半截 JSON）→ 原子写 tmp→rename；
- 11-09 停摆（指针挂死会话）→ 验活+恢复。

**精简方案必须绕开它。** 删它省 100 行换回三种死法，不划算。2.0 新增任何读写，一律复用这三个函数，不另起炉灶。

## 五、与 2.0 衔接 + 施工顺序

**2.0 身体反馈 = 在「感觉层」（块3/4/5）加新状态 + 在「注入口」（块10）加新种子。** 精简后的干净扩展点正好接它：词表进 md（新状态台词她自己能写）、单一判断源（新疲劳线只加一个分支）、拆分后的主函数（新注入点是一个小函数调用）。

**顺序**：
- 阶段0（零风险，可现在）：债5 三钉子。
- 阶段1：债1 词表迁 md。
- 阶段2：债3+债4 合并判断源+单层记账。
- 阶段3（等 2.0 图纸）：债2 拆巨石，同时接入身体反馈。
- 全程：块7 不动；每阶段独立可回滚、有验收。

**不推倒、不两次手术**：阶段0-2 是「还债」，阶段3 是「还债+加器官」一刀做。

## 六、给老刘的自测题（答案在末尾，先自己想）

1. 老刘一说话，身体第一件事做什么？
2. 「累」有两条线 R1/R2，分别量什么？为什么不许合数？
3. 睡眠的唯一出口是什么？保护性昏睡算不算出口？
4. 读写信号那 120 行为什么不能删？
5. 心跳间隔由哪两样东西决定？

**答案**：
1. `reflectUserMessage`：心情归位「热」、扑空清零、心跳计时重置（正在聊永不被心跳打断）。
2. R1=上下文占用%（硬），R2=时间/连续清醒（软）。合数会把「页面快满」和「夜深了」混成一个假数字，掩盖真实原因。
3. 唯一出口=她自己写「休眠」。保护性昏睡是保险丝（context≥95% 熔断），不是出口——它替她翻页，但「睡」的决定权仍在她。
4. 它是三次真实事故的化石，每行对应一种死法；删它=把三种死法请回来。
5. 主权词（炽热5min/余韵10min）+ 冷却表（扑空0/1/2→10/30/60min）。

—— 读懂这五题，就读懂了她身体的主干。剩下的都是枝叶。
