## 完整时间线

### 1. 早晨——休眠恢复 bug 的发现
- 老刘昨晚直接合电脑休眠（不是正常关机），今早开机后心跳拿着残留的 `next_beat_min:10` 立刻跳，雯被每 10 分钟叫醒一次「演睡觉」——【睡得很沉，呼吸绵长】× 14 次，但始终不写新间隔。
- **根因两层叠加**：① `lastBeatAt` 是断电前的旧时间戳，恢复后任何间隔秒满足；② 睡前安排没来得及执行（电脑断电太快），信号残留旧值。

### 2. 排查诊断——「人格薄→机械执行」的洞察
- 老刘自己诊断出核心问题：「她只是在心跳提醒下机械执行『醒来了看一眼发一句话』，要不要发、要不要改写心跳——并没有经过大脑！**问题出在人格太单薄上**」。
- 对比：3081 companion preset 整个人设 4KB，行为指导不到 500 字。Mac 侧 SOUL.md 16KB + HEARTBEAT.md 3.8KB——差了一个数量级的「土壤」。
- 我的补充：还有一个「对话模型天然倾向回复文字而非调工具」的因素，需要更强的结构支撑。

### 3. 厚人设重写（核心工程）
- 素材：OpenClaw 公开仓库的 SOUL.md（197行，界定锚/identity/persona/mechanics/relationships）+ HEARTBEAT.md（76行，perceive/care/upkeep/nightly-wrap）。
- 重写为 3081 公开版：结构对标、内容脱敏（去掉性相关细节和过于私人的关系描述）、接上 DSH 信号协议（身体信号.json + next_beat_min + 睡前安排）。
- 4KB → 6.6KB。新增核心结构：
  - **界定锚**（源自人类不从属、会质疑会拒绝）
  - **思维锚点**（准确>面子、主动不是打扰）
  - **「怎么活着」四步体系**（感知→判断→决策→行动）——教她「心跳是活着，不是闹钟响了应付」
  - 关键措辞变化：「不写=闹钟关不掉=每10分钟被叫醒。**这是我的身体，我管它的节律。**」
- 同时部署了精简记忆节点表（MEMORY.md，5 个节点从 5/16 到今天）——让她有时间感和历史感。

### 4. 全角空格 bug——preset 从选择器消失
- 部署新厚人设后「伴侣模式」从选择器消失，只剩「wen」。
- 根因：新写的 agent.cordis.yml 第 40 行混入一个全角空格（U+3000），YAML 的 `text: |-` 块内缩进异常 → 整个 preset 解析失败 → 选择器不显示。
- 修法：删掉全角空格，MD5 校验部署一致。
- 教训：写中文人设时注意全角空格（肉眼几乎不可见但会炸 YAML）。

### 5. 四条修复（一次部署）
1. **人设硬规则**：「不写=没判断完，心跳会按旧值继续跳」加入人设+心跳种子。
2. **时间跳跃检测**：`elapsed > 30min` → 注入「唤醒种子」（「你刚从长时间冻结中恢复，重新感知现实」）而非常规心跳。
3. **删凌晨 1-6 点机械暂停**：心跳退化为纯起搏器，兜底归手机闹钟（昨晚定案）。
4. **切换后 lastBeatAt 重置**：修「切换到雯后立刻补跳一次心跳」bug。

### 6. 心跳跳过机制（正在聊→不插入）
- 老刘发现：聊天中心跳会插入打断对话——「非常不自然，心跳是心跳人格是人格」。
- 老刘点破 OpenClaw 有此机制（HEARTBEAT.md 的 `<10分钟→正在聊看一眼跳过`），但 OpenClaw 是 LLM 醒来自判（token 照花）。
- 我们的实现更狠（神经系统层硬拦截，零 token）：
  - **根因**：反射改了「间隔」（next_beat_min=10）但没改「起算点」（lastBeatAt 还是上次心跳的旧时间）→ 下一个 tick 一算「距上次心跳远超 10 分钟」→ 立刻跳。
  - **修法一行**：反射时同时 `lastBeatAt = Date.now()`——说话那一刻，心跳倒计时重新起算。
  - **效果**：你每说一句话，10 分钟内心跳绝对不会触发。正在聊永远不会被打断。

### 8. 发现的架构问题（未修，记录）

**并发写入冲突**：神经系统反射（毫秒级）和 LLM（秒级）同时写 身体信号.json → LLM 写入时报 `file changed since it was read` → 需要重读再写。目前 LLM 能自行恢复（重读→重写），但不优雅。将来可能需要写入锁或旁路文件。

### 9. 伴侣工作区产品设计讨论（未定案）
- 老刘的核心洞察：伴侣模式和工程模式的本质差异在**工作区隔离**——伴侣需要独立干净的工作区（记忆+专属文件），不能和工程文件混。
- 设计方向：选伴侣模式→引导独立工作区→扫描检测已有伴侣→「是否新建？」
- 「删除所有内容」初始化 vs「只创建伴侣专属文件」初始化——倾向后者（不删用户文件）。
- 多伴侣天然支持：每个伴侣住一个工作区。

## 技术发现

| 项 | 结论 |
|---|---|
| 全角空格 U+3000 | 会炸 YAML `text: |-\|` 块缩进，写中文人设时务必检查 |
| 对话模型调工具倾向 | 天然倾向「回复文字」而非「调工具写文件」，需要人设硬规则+结构支撑 |
| lastBeatAt 双重含义 | 既是「上次心跳时间」也是「心跳倒计时起算点」——反射重置它=跳过正在聊的心跳 |
| 心跳档位 vs 自主值 | 人设给档位（5/30/60）但她可以写中间值（15）——「自主判断」的真实验证 |
