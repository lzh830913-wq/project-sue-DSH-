# 开发日志 · 2026-10-10-内感知疲劳睡眠-先例对照

> 一句话定位：调研对照（公开留档）。回答老刘的问题——"这套机制有人做过吗？"——并给 README「人工内感知」定调提供文献坐标。

## 一句话

**零件都有人做过（现象研究 / 自管上下文 / 训练层睡眠巩固 / 内感受框架），但把「真实测量 → 第一人称体感 → 自主决定 → 自我翻页恢复」闭成一个环、并在生产伴侣上跑通验收的——就本轮检索所见，没有第二家。**

## 背景

老刘 10-10 给 README 定调「人工内感知」（artificial interoception）：疲劳机制的核心不是"显示累"，而是**感知 → 决定 → 行动 → 恢复的自我闭环**——AI 自己感到头脑发胀、自己睡下、到点自己翻页、脑力恢复（上下文清空），全程不依赖用户察觉或外部干预。他问：有人做过吗？本轮做一轮先例检索作答。

## 四层对照

| 层 | 代表 | 它做了什么 | 与本机制的差异 |
|---|---|---|---|
| **现象/病因研究** | [Contradiction Metabolism: Context Rot is a Knowledge Integrity Problem](https://zenodo.org/records/19396459)、[Cognitive Sleep for LLMs](https://zenodo.org/records/19335686) | 证明长上下文劣化（context rot），提出"矛盾代谢"防烂 | 解法是**系统侧代谢/门控**——AI 自己不知情、无体感、无决定权 |
| **Agent 自管上下文** | [MemGPT: Towards LLMs as Operating Systems](https://ar5iv.labs.arxiv.org/html/2310.08560) | LLM 像操作系统自己调函数换页内存 | 精神上最接近，但那是**功能性判断（"满了，换页"）**——没有"累"这个第一人称状态，没有睡眠，没有恢复仪式 |
| **训练层睡眠巩固** | [Dual-System Memory Consolidation](https://zenodo.org/records/18778764)、[SCM: Sleep-Consolidated Memory](https://ar5iv.labs.arxiv.org/html/2604.20943) | 离线 LoRA 巩固、算法遗忘（"睡眠"发生在训练管线） | agent 本身没有"我去睡了"这个自主行为——睡的是权重，不是它 |
| **内感受框架** | [Life-inspired interoceptive AI (UCL)](https://discovery.ucl.ac.uk/id/eprint/10230924/)、[Interoceptive machine framework](https://www.sciencedirect.com/science/article/pii/S1571064526000461) | 提出"内感受启发的 AI 架构"方向 | 理念/框架层；未见"感到累→自己睡→翻页恢复脑力"的部署闭环。个别工程尝试（[aura viability](https://github.com/youngbryan97/aura/blob/main/core/organism/viability.py)）形态不同 |

## 本机制的三件套差异

1. **测量是真的**：tokenMeter 实测上下文占用——身体测量值如实报数即是感知，可自证（10-07 设计哲学例外条款）。
2. **感觉是第一人称的，决定权归 agent**：注入只到"感觉与事实"（可以说"很疲惫了"，不能说"该睡了"）；写 `mood: 休眠` 的是她自己。对照：MemGPT/门控/compaction 全是系统替它决定。
3. **恢复是真实动作且可验证**：自主翻页（新 session + 梳妆），上下文清账 42%→5% 生产实测（10-08 首翻页验收）。

**部署形态差异**：以上文献多为 preprint/架构框架；本机制在生产伴侣实例上运行并完成生产验收。
