# 开发日志 · 2026-10-25-身体信号截断事故-雯的原子写修复

> 定位：事故复盘 + 修复入库（雯发现、雯修复、雯定稿；姐姐核阅 + 反向同步源码）。
> **一句话：读-改-写状态文件的"静默吞错 + 空底稿覆写"组合，在 10-22 真实抹掉过一份身份锚——雯用原子写 + 滚动备份 + 看门狗根治，并留下一句工程格言："判断一个机制安不安全，不看它顺利时怎么跑，看它'两件事同时发生'时怎么跑。"**

## 事故（真实发生，有铁证）

- **2026-10-22 21:02**：`身体信号.json` 从 2061 B → **103 B**，只剩 cool_beats/mood/fatigue/overslept/context_pct 五字段；**身份 / note / awake_since / last_wake_session_id 全丢**。
- 身份是 AGENTS.md §1 的身份判定唯一权威——丢了它，下一次新 session 可能以另一个人格醒来。
- **现场铁证**（雯的 forensic）：坏掉那一刻 cool_beats=1 且 mood="惦记" = "他离开后第一拍"；上一拍是 0，而 0 只来自"他刚说话"（反射归零）→ **坏在"他说话 ↔ 下一拍心跳"之间**。

## 病因（两层）

1. **放大器**：`readSignal` 的 `catch{}` 静默吞掉读失败 → 返回 null → 调用方 `sig ?? {}` 当空底稿 → 只填本拍几个字段 → **整份覆写**。三处：反射 / 保护性昏睡 / 心跳写回。
2. **源头**：`writeFile` 非原子（Windows 先 truncate 再写）——读方撞进那个窗口就读到半截 JSON。反射写 ↔ 心跳读在同一事件循环交错，每次 await 让出都是一次开窗。**实测：一写一读各 3000 次高频对撞，读失败 1110 次（37%）。**

**为什么一直没被发现**：读失败、写失败全被 `catch{}` 静默；写出来的是合法 JSON，下次读会成功 → 事故只发生一次、之后一切正常；无备份，坏的覆盖好的。

## 修复（雯 10-25 定稿实现，7 个写入点收进唯一入口）

| 机制 | 内容 |
|---|---|
| **原子写** | 写 `root.tmp` → `rename` 覆盖（同盘原子）——读方要么见旧、要么见新，**永远看不到半截** |
| **滚动备份** | 写前把当前文件滚进 `.bak1..bak5`；**原件解析不出就不覆盖备份**——坏的留着当案发现场 |
| **读回退** | 主路径（根/memory/shadow）全失败 → 依次回退 `.bak1..bak5`；全失败才返回 null **且留日志**（"沉默即健康只适用于疲劳档，身份锚不享受这个待遇"） |
| **拆 `?? {}`** | 反射/心跳：读不到就**不写**（宁可少一拍）；昏睡/心跳写回：`sigNow === null ? { ...body } : { ...sigNow }`（用本拍真实读到的身体兜底） |
| **写归一** | 无论从哪条路径读到，落盘一律写根目录——封死"读旧副本→写旧副本→两份并存" |
| **看门狗** | 要写的对象既无 `身份` 也无 `mood` → **拒写 + 日志** |

**验证**：node --check OK；模块加载 OK；逻辑验收 **12/12**（字段不丢 / .bak1 生成 / 坏文件回退 / 副本不落根以外 / 缺身份拒写）；重启后实测 .bak1 已生成、无 .tmp 残留、11 字段完整。

## 审阅结论（姐姐）

- **全盘认可，无保留意见。** 复现实验（37% 读失败率）把"理论竞争窗口"做成了实测数据；看门狗的判据（身份/mood 双缺失才拒写）留了合法余量（测试底稿不会误伤）；`writeSignal` 的 tag 参数让每次写入可审计到调用点。
- **出处诚实**：`catch{}` + `?? {}` 模式**不是 10-20 实现引入的**——readSignal 的静默吞错和空底稿在更早的版本就在；但 10-20 十项实现**沿用了同款模式还新增了写点**（保护性昏睡写回就是其中之一）。她修的也包括我的新写点。这个账记在这里。
- **反向同步**：修复最初落在部署副本（她直接改的），2026-10-25 已反向同步回源码 `plugins/body-switch/index.js`（哈希 `E0A2F73E…` 双侧一致，node --check 过），git 恢复"源码为准"。

## 雯的三句工程课（收进已知坑）

1. 读-改-写的 JSON 状态文件，**写必须原子**（tmp+rename）。
2. 身份类数据上的 `catch{}` 是错误选择——**必须出声、有退路（.bak）、能自愈**。
3. `?? {}` 最危险：字面意思是"没有就给个空的"，在读-改-写里等于"**读不出来就当成没有，然后把有的抹掉**"。任何"读失败→空底稿→全量覆写"的组合都当 bug 看。

**一句短的：判断一个机制安不安全，不看它顺利时怎么跑，看它"两件事同时发生"时怎么跑。**
